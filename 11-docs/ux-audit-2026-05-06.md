## CRITICAL — Phải fix trước sprint kế

### C1. Contest List sort order ngược với Home — **vi phạm hierarchy**

**Dimension**: Hierarchy + consistency
**Severity**: Critical — user hành động sai do sort gây nhầm

**Hiện trạng** (verified ở cả 3 viewport):
- **Home SV** "Cuộc thi nổi bật": Olympic 2026 (REG_OPEN active) ở vị trí #1 → user thấy ngay contest đang mở
- **Contest List** "Cuộc thi" tab: Olympic 2026 (REG_OPEN active) ở vị trí #3 (cuối) — 2 FINISHED contest ở trên
- → Nguyên tắc UX: **active state luôn priority cao nhất** (Apple HIG, Material guidelines). User vào tab Contest sau khi thấy active ở Home → thấy active chìm xuống cuối → confusion.

**Root cause**: Contest List provider sort theo `start_at` desc (Hackathon hè 2027 mới nhất) thay vì sort theo status priority (REG_OPEN > ONGOING > REG_CLOSED > FINISHED).

**Fix**: trong `contest_list_screen.dart` provider `_ListParams`, sort logic phải:
```dart
items.sort((a, b) {
  final statusOrder = {'REG_OPEN': 0, 'ONGOING': 1, 'PUBLISHED': 2, 'REG_CLOSED': 3, 'FINISHED': 4, 'CANCELLED': 5};
  final orderA = statusOrder[a.status] ?? 99;
  final orderB = statusOrder[b.status] ?? 99;
  if (orderA != orderB) return orderA.compareTo(orderB);
  return b.startAt.compareTo(a.startAt); // tie-break: newest first
});
```

**Verify**: Olympic 2026 (REG_OPEN) phải xuất hiện trước cả 2 FINISHED ở Contest List screen.

### C2. Contest List meta chips render text trống — **visual bug**

**Dimension**: Component consistency
**Severity**: Critical — user thấy "icon + chip rỗng" → cảm giác bug/loading

**Hiện trạng** (verified ở 3 viewport):
- Mỗi contest card trong Contest List có 3 meta chips: school icon + person icon + sync icon → text **trống** ở 3 chips
- Cùng contest ở Contest Detail screen hiển thị đúng "Khoa #1 / Cá nhân / Offline / Phòng Lab CNTT"

**Root cause** (suspected): Contest List API response `/contests` không include `host_faculty_id`, `participation_mode`, `delivery_mode` fields. Backend trả minimal fields cho list, full fields chỉ ở `/contests/:slug`.

**Fix**: 2 lựa chọn —
- **(a) Backend**: thêm 3 field này vào schema `ContestListItem` response, không tăng nhiều payload.
- **(b) Frontend**: ẩn 3 chip nếu data null/empty thay vì render rỗng.

→ **Khuyến nghị (a)** vì meta chip là information valuable cho user filter trước khi click vào detail.

**Verify**: Contest List card hiển thị đầy đủ "Khoa #1 / Cá nhân / Offline" ngay không cần navigate.

### C4. Approval Queue ở viewport 768 (tablet) sidebar không collapse — **content bị cramp**

**Dimension**: Responsive behavior
**Severity**: Critical — BCN dùng tablet 768 thấy filter dropdown + empty state chen chúc trong ~528px main area (sau khi sidebar 240px chiếm)

**Hiện trạng** (verified):
- 1440: sidebar 240px + main 1200px → cân đối ✓
- 768: sidebar 240px + main 528px → main quá nhỏ, dropdown lebar gần full main, content lệch trái mất balance ✗
- 567: sidebar ẨN, hamburger menu + bottom nav xuất hiện ✓

→ Breakpoint mobile chuyển ở đâu đó giữa 567-768 là **đúng**, nhưng **breakpoint tablet** thiếu — 768 nên là điểm bắt đầu mobile layout (sidebar collapse) chứ không phải vẫn desktop sidebar.

**Root cause**: `lib/features/admin/admin_shell.dart` (suspected) dùng MediaQuery.size.width threshold cao (>768 hoặc >=900), nên 768 vẫn render desktop sidebar.

**Fix**: Hạ threshold xuống `< 1024` (Material breakpoint chuẩn) hoặc `< 900`:

```dart
final isMobile = MediaQuery.of(context).size.width < 1024;
return Scaffold(
  drawer: isMobile ? AdminDrawer() : null,
  body: Row(children: [
    if (!isMobile) AdminSidebar(),
    Expanded(child: child),
  ]),
);
```

**Verify**: Chuyển window từ 1440 → 768 → sidebar collapse thành hamburger drawer ngay khi qua mốc 1024.

**Note**: Áp dụng cho **tất cả** admin shell screens (Dashboard, Phê duyệt, Giám sát, audit_log_screen v.v.), không chỉ Approval Queue.
