| Mức | Số issue | Đánh giá |

1. **Quick fix**: thêm `lang="vi"` + nới lỏng viewport zoom (em đã làm)
2. **Long-term**: Cần wrap widget bằng `Semantics(label:...)` hoặc switch sang `--web-renderer html` để screen reader thấy nội dung. Phase C tiếp.

- **No keyboard / screen reader test**: axe automated chỉ check static DOM. Manual keyboard nav + NVDA/VoiceOver test cần human tester.

## Findings

### Critical

#### A1. `meta-viewport` — Flutter disable zoom

**Dimension**: Operable (1.4.4 Resize text)
**Severity**: Critical (axe)
**Áp dụng**: 8/8 scans

**Hiện trạng**:
```html
<meta flt-viewport="" name="viewport"
      content="width=device-width, initial-scale=1.0,
               maximum-scale=1.0, user-scalable=no">
```

Flutter framework **tự inject** meta viewport này (attribute `flt-viewport=""`) khi app khởi động, **disable zoom** với `maximum-scale=1.0, user-scalable=no`.

**Impact**: User thị lực kém **không zoom được tới 200%** như WCAG 1.4.4 yêu cầu. Người dùng buộc mua kính phụ hoặc dùng OS zoom (ảnh hưởng toàn hệ thống).

**Root cause**: Flutter design choice — canvaskit dùng device pixel ratio scaling nội bộ, OS zoom có thể conflict.

**Fix em đã apply** (`web/index.html`):
```javascript
window.addEventListener('flutter-first-frame', function() {
  var v = document.querySelector('meta[flt-viewport]');
  if (v) v.setAttribute('content', 'width=device-width, initial-scale=1.0');
});
```

→ Sau frame đầu render, override viewport bỏ scale lock. Test re-scan để verify.

**Risk**: Có thể Flutter rendering hơi mờ ở zoom level lẻ (vd 175%) vì canvas scale nội bộ. Trade-off chấp nhận để pass WCAG.

#### A2. `button-name` — Empty button (Claude extension overlay)

**Severity**: Critical (axe)
**Áp dụng**: 8/8 scans
**Status**: **False positive**

**Hiện trạng**:
```html
<button class="size-10 absolute z-[-1] bottom-[10px] flex-center p-0
              outline-none border-none text-title bg-bg2 cursor-pointer
              hover:text-primary transition-colors -left-[38px]
              rounded-tl-full rounded...
```

Class `size-10`, `absolute`, `text-title bg-bg2`, `rounded-tl-full` → đây là **button của Claude in Chrome extension** (overlay anchor floating bottom-right page), không phải Flutter app.

**Action**: Document false positive, không fix trong code Flutter. Khi build production deploy lên Cloudflare Pages thì Claude extension button không tồn tại → vi phạm này biến mất.

### Serious

#### A3. `html-has-lang` — Missing lang attribute

**Dimension**: Understandable (3.1.1 Language of Page)
**Severity**: Serious (axe)
**Áp dụng**: 8/8 scans

**Hiện trạng**: `<html>` không có attribute `lang` → screen reader không biết phát âm tiếng Việt vs Anh.

**Fix em đã apply** (`web/index.html`):
```html
<html lang="vi">
```

→ Screen reader sẽ phát âm theo phonetic tiếng Việt. Re-scan verify violation gone.

## META issue — Flutter canvaskit Semantics tree rỗng

**Severity**: Critical (silent — không xuất hiện trong axe report)
**Áp dụng**: Toàn app

### Hiện trạng

Flutter web mặc định dùng renderer **canvaskit** (Skia → WebGL → canvas pixel-based). Mọi text, button, input render vào `<canvas>` element duy nhất:

```html
<flt-glass-pane>
  <canvas><!-- Flutter renders here --></canvas>
  <flt-semantics-host></flt-semantics-host> <!-- EMPTY: 0 children -->
</flt-glass-pane>
```

Khi axe scan `flt-semantics-host`, phát hiện **0 children** → screen reader không có gì để đọc.

### Tại sao axe không flag?

axe-core kiểm tra rules áp dụng vào DOM elements. Flutter app không tạo `<button>`, `<input>` standard → axe không có element nào để check rules `aria-*`, `label-*`, `nested-interactive`. **Silent failure**.

### Impact

- **Screen reader (NVDA/JAWS/VoiceOver)**: User mù **không nghe được** label form, button, content.
- **Keyboard nav**: Tab key có thể không di chuyển focus qua các Flutter widgets (canvas captures keys).
- **Voice control (Dragon, Voice Access)**: Không click được button qua voice.

→ App **inaccessible cho user disability** mặc dù axe không flag.

### Fix options

#### Option A: Switch sang `--web-renderer html`

```bash
flutter build web --web-renderer html --release
```

- HTML renderer dùng DOM elements thật (`<button>`, `<input>`) → axe + screen reader thấy được
- **Trade-off**: Slow hơn canvaskit cho complex UI (animation, gradient). Phù hợp app form-heavy.
- **Risk**: Some Flutter widgets render khác giữa 2 renderers (vd `BackdropFilter`)
- **Recommend**: Test build HTML renderer, evaluate render quality + perf, decide.

#### Option B: Wrap widgets bằng `Semantics()`

Thêm `Semantics` widget cho mọi interactive element:

```dart
Semantics(
  label: 'Đăng nhập với email PTIT',
  button: true,
  child: FilledButton(
    onPressed: _submit,
    child: const Text('Đăng nhập'),
  ),
)
```

- Flutter canvaskit **TỰ động enable Semantics tree** nếu detect screen reader running
- Khi enabled, render `<flt-semantics>` overlay với role/label cho mỗi widget
- Phải audit toàn app + wrap manual ~50-100 widgets
- **Effort**: Cao (~10-20h) nhưng giữ canvaskit

#### Option C: Combo (recommended)

- **Short-term** (Sprint 3): Enable Flutter `enableAccessibility` + thêm `Semantics()` cho top critical components (Login form, contest cards, primary buttons)
- **Long-term** (post-defense): Eval HTML renderer cho production deploy
